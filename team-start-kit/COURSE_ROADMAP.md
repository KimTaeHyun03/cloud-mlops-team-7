## 네 번의 마일스톤

### M1 — 모델을 다시 만들 수 있다

- 시점: 4주차 종료
- 필수: 문제정의서, 데이터 카드, 학습 코드, 평가 지표, 모델 저장 경로
- 질문: 다른 팀원이 README만 보고 같은 모델을 만들 수 있는가?

### M2 — 다른 사람이 링크로 사용할 수 있다

- 시점: 8주차 종료
- 필수: API, 데모 화면, ECR 이미지, EC2 배포, 성공·실패 테스트
- 질문: 팀원 노트북을 끄어도 서비스가 실행되는가?

### M3 — 서비스의 이상을 발견하고 조치할 수 있다

- 시점: 13주차 종료
- 필수: 자동 배포, 로그·메트릭, 알람, 장애 조치 절차, 비용 확인
- 질문: 오류가 났을 때 누가 어떤 화면을 먼저 보는가?

### M4 — 다른 팀이 재현하고 사용할 수 있다

- 시점: 15주차
- 필수: 실행 가능한 저장소, README, 시연, 운영·정리 문서, 개인 기여 기록
- 질문: 만든 팀의 설명 없이도 다른 팀이 실행할 수 있는가?

## 매주 수업이 끝나기 전 5분

1. 내가 수정한 파일과 커밋을 확인한다.
2. 팀의 오늘 결과를 README·이슈·체크리스트에 남긴다.
3. 실행 중인 AWS 리소스와 비용 발생 가능성을 확인한다.
4. 다음 주 담당자와 준비할 파일을 확인한다.

## 장표 제작 지시

- 1주차에는 `전체 15주`, `M1~M4`, `개인 증거`를 3장으로 나누어 보여준다.
- 2~15주차는 오늘 행만 크게 표시한 `지금의 위치` 장표 1장을 앞부분에 넣는다.
- 표 전체를 한 장에 작게 넣지 말고, 4개 단계를 가로 흐름으로 보여준다.
- 역할 순환이 시작되는 5·9·13주차에는 새 역할과 이전 역할의 인수인계 항목을 함께 보여준다.
