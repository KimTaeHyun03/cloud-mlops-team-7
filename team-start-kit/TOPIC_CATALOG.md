# 클라우드 MLOps 실습 프로젝트 예시 주제

운영 방법: 1주차에 팀별로 후보 2개를 고르고, 3주차에 실제 데이터를 다운로드해 검증한 뒤 1개를 확정한다.

## 우선 추천 3개

### 1. 날씨와 시간에 따른 서울 자전거 대여량 예측 — 입문 추천

- 사용자: 대여소에 자전거를 미리 배치하는 운영자
- 입력: 시간, 기온, 습도, 풍속, 강수량, 계절, 공휴일
- 출력: 한 시간에 필요한 자전거 수
- 최소 화면: 날씨·시간을 입력하면 예상 대여량과 범위를 표시
- 운영 메특: API 오류율, 응답 시간, MAE 변화
- 데이터: 8,760행, 13개 열, 결측치 없음, 회귀, CC BY 4.0
- 링크: [UCI Seoul Bike Sharing Demand](https://archive.ics.uci.edu/dataset/560/seoul+bike+sharing+demand)
- 난이도: ★☆☆

### 2. 건물 구조에 따른 난방·냉방 부하 예측 — 입문 추천

- 사용자: 건물 설계안을 비교하는 에너지 담당자
- 입력: 표면적, 벽면적, 지붕면적, 높이, 방향, 창면 비율
- 출력: 난방 또는 냉방 부하
- 최소 화면: 건물 조건을 바꾸면 예상 부하를 비교
- 운영 메특: API 오류율, 응답 시간, RMSE 변화
- 데이터: 768행, 8개 입력, 2개 목표, 결측치 없음, 회귀, CC BY 4.0
- 링크: [UCI Energy Efficiency](https://archive.ics.uci.edu/dataset/242/energy+efficiency)
- 난이도: ★☆☆

### 3. 센서 값으로 설비 고장 가능성 판별 — 분류 추천

- 사용자: 설비 점검 순서를 정하는 생산 운영자
- 입력: 기온, 회전 속도, 토크, 공구 마모 시간
- 출력: 고장 가능성과 점검 우선순위
- 최소 화면: 센서 값을 입력하면 `점검 권장 / 정상 범위`를 표시
- 운영 메특: 장애 후 재현율, 오탐지율, API 응답 시간
- 데이터: 10,000행, 핵심 센서 특성 6개, 합성 데이터, 분류, CC BY 4.0
- 주의: 고장 행이 적어 정확도만 보면 안 되며 재현율·정밀도를 함께 비교한다.
- 링크: [UCI AI4I 2020 Predictive Maintenance](https://archive.ics.uci.edu/dataset/601/ai4i)
- 난이도: ★★☆

## 추가 후보 5개

### 4. 환경 센서로 강의실 사용 여부 판별

- 입력 → 출력: 기온·습도·조도·CO₂ → `사용 중 / 비어 있음`
- 데모: 센서 값 슬라이더와 사용 여부 표시
- 데이터: 20,560행, 이진 분류, 결측치 없음, CC BY 4.0
- 링크: [UCI Occupancy Detection](https://archive.ics.uci.edu/dataset/357/occupancy-detection)
- 난이도: ★★☆

### 5. 온도·습도로 가정 전력 사용량 예측

- 입력 → 출력: 실내외 온도·습도·날씨 → 예상 가전제품 전력량
- 데모: 조건을 바꾸며 예상 전력량과 구간을 표시
- 데이터: 19,735행, 28개 특성, 회귀, 시간 특성 포함, CC BY 4.0
- 링크: [UCI Appliances Energy Prediction](https://archive.ics.uci.edu/dataset/374/appliances+energy+prediction)
- 난이도: ★★☆

### 6. 콩 알의 형태 치수로 7개 품종 분류

- 입력 → 출력: 면적·둘레·축 길이·원형도 → 콩 품종
- 데모: 치수를 입력하면 예측 품종과 확률 상위 3개를 표시
- 데이터: 13,611행, 16개 특성, 7개 클래스, 결측치 없음, CC BY 4.0
- 링크: [UCI Dry Bean](https://archive.ics.uci.edu/dataset/602/dry)
- 난이도: ★★☆

### 7. 콘크리트 배합과 숙성 기간으로 압축 강도 예측

- 입력 → 출력: 시멘트·물·골재·숙성 일수 → 예상 압축 강도
- 데모: 배합비와 일수를 조정하며 예상 강도를 비교
- 데이터: 1,030행, 8개 입력, 회귀, 결측치 없음, CC BY 4.0
- 링크: [UCI Concrete Compressive Strength](https://archive.ics.uci.edu/dataset/165/concrete+compressive+strength)
- 난이도: ★☆☆

### 8. 웹 방문 행동으로 구매 세션 여부 판별

- 입력 → 출력: 페이지 수·체류 시간·반송률·방문 유형 → 구매 완료 가능성
- 데모: 현재 세션의 지표를 입력하면 구매 가능성을 표시
- 데이터: 12,330행, 17개 특성, 이진 분류, 결측치 없음, CC BY 4.0
- 주의: 구매 세션 비율이 낮으므로 F1·재현율을 함께 본다. 개인을 차별하는 자동 결정으로 사용하지 않는다.
- 링크: [UCI Online Shoppers Purchasing Intention](https://archive.ics.uci.edu/dataset/468/online+shoppers+purchasing+intention+dataset)
- 난이도: ★★☆

## 팀이 주제 2개를 고르는 방법

각 후보를 0~2점으로 평가한다.

| 질문 | 0점 | 1점 | 2점 |
|---|---|---|---|
| 사용자가 보이는가? | 누가 쓰는지 모름 | 대략 알림 | 특정 사용자와 상황이 있음 |
| 입력·출력이 명확한가? | 설명 못 함 | 하나만 설명 | 둘 다 한 문장으로 설명 |
| 데이터를 바로 받을 수 있는가? | 접근 못 함 | 가공이 필요 | 바로 다운로드 가능 |
| 15주 안에 화면으로 보여줄 수 있는가? | 대규모 추가 기술 필요 | 기능 축소 필요 | 입력폼·결과로 구성 가능 |
| 팀원이 이해하는가? | 한 명만 이해 | 절반 정도 이해 | 모두 30초 안에 설명 가능 |

- 8점 이상: 후보로 제출
- 6~7점: 범위를 줄인 후 재평가
- 5점 이하: 다른 주제 선택

## 3주차 최종 확정 조건

- [ ] 데이터 파일을 실제로 다운로드했다.
- [ ] 행 수, 열 수, 타깃 열, 결측치를 확인했다.
- [ ] 데이터 라이선스와 출처 표기 방법을 확인했다.
- [ ] 베이스라인 학습이 10분 안에 끝난다.
- [ ] API 입력 JSON과 결과 JSON 예시를 작성했다.
- [ ] 학생 한 명이 1분 안에 데모 화면을 설명할 수 있다.

## 선택하지 않는 주제

- 채용, 해고, 신용, 보험, 질병, 범죄 가능성을 자동으로 판단하는 주제
- 얼굴·음성·걸음걸이로 개인을 식별하는 주제
- 개인정보를 허락 없이 수집해야 하는 주제
- 실제 데이터 파일을 수업 중 확보할 수 없는 주제
- GPU·대규모 이미지·LLM 학습이 필수인 주제

## 장표에 넣을 구성

1. “아이디어를 짜내지 말고, 완성 가능한 후보를 고르세요”
2. 우선 추천 3개를 각각 한 장에 `사용자 → 입력 → 예측 → 화면`으로 표현
3. 추가 후보 5개를 2장에 나누어 제시
4. 주제 점수표와 8점 통과 기준
5. 1주차 활동: 후보 2개를 `PROJECT_IDEA_CARD.md`에 작성
6. 3주차 활동: 데이터 검증 체크리스트 통과 후 1개 확정

> 자료 검증: 위 8개 후보는 UCI Machine Learning Repository의 각 데이터셋 상세 페이지에서 행·특성·과제·결측치·라이선스를 2026-08-31에 확인했다.
