## 학생 화면 본문

### 1. 실제 데모로 배우는 AI와 MLOps 실습

중고차 예측 서비스를 만들었던 대화를 처음부터 따라갑니다. 이어서 지하철 서비스를 만들고 고쳤던 과정을 봅니다. 요청을 쓰고, 결과를 열어 확인하고, 근거를 붙여 다시 요청하는 방법을 연습합니다. MLOps는 이 과정의 자료·코드·검사·실행 환경을 기록해 다시 실행하고 고칠 수 있게 관리하는 일입니다.

| 확인할 내용 | 실제 자료와 해석 |
|---|---|
| 1교시 50분 | usedcars: 데이터 검토, 가격 예측, 오차 확인, 입력 추가, 웹 서비스와 배포. |
| 2교시 50분 | 지하철: 데이터 가능성 검토, 예측·경로 연결, 화면 수정, 로컬 실행과 배포. |
| 3·4교시 100분 | 우리 팀 프로젝트에서 같은 방식으로 한 단계를 실행하고 다른 팀원이 재확인합니다. |

### 32. 지하철 모델은 최근 조사값을 얼마나 반영할지 정했다

| 확인할 내용 | 실제 자료와 해석 |
|---|---|
| 계산 예 · 설명용 | 과거 예상 40%, 새 관측 60%, 최근 값 비중 0.75라면 60×0.75 + 40×0.25 = 55%. |
| 알파 α | 최근 값에 주는 비중. α=1이면 최신 관측을 그대로 사용합니다. |
| 실제 학습 | 1, 0.75, 0.5, 0.25, 0.1을 비교해 노선별로 덜 틀린 값을 선택. 동률이면 단순한 α=1 우선. |

자료를 한 행 설명하고, 실행 결과를 확인했습니다. 이제 발견한 문제 하나를 고르는 시간입니다. 여러 기능을 동시에 바꾸기보다 결과를 다시 확인할 수 있는 변경을 정합니다.

**학생 기록:** 수정할 문제 하나, 재현 조건, 기대 결과

### 55. 수정 요청: 관찰한 현상과 기대 결과를 함께 쓴다

지하철 경로 수정 대화처럼 재현 가능한 요청을 보냅니다. AI가 바꾼 이유와 검사 방법도 결과에 포함하도록 합니다.

### 56. 실행 3: 수정 후 같은 입력으로 다시 검사한다

입력과 평가 조건을 유지한 채 수정된 프로그램을 실행합니다. 이전에 실패한 조건이 해결됐는지, 정상 동작하던 조건도 유지되는지 확인합니다.

| 확인할 내용 | 실제 자료와 해석 |
|---|---|
| 재검사 | 같은 입력의 수정 전후 출력 비교. 모델이 바뀌면 모델 버전과 평가 범위를 기록. |
| 주변 조건 | 다른 시각, 자료 없음, 빈 입력 등 이번 변경과 관련된 조건 한두 개 추가. |
| 완료 조건 | 문제 재현 자료와 해결 결과를 나란히 저장. 실행하지 않은 검사를 통과했다고 적지 않음. |

**학생 기록:** 같은 입력의 수정 전후 결과와 새로 확인한 조건

### 57. 다른 팀원이 처음부터 결과를 열어 본다

작업하지 않은 팀원이 안내문을 보고 같은 입력을 실행하거나 결과를 대조합니다. 실행 환경이나 자료가 없는 경우도 그대로 기록합니다.

| 확인할 내용 | 실제 자료와 해석 |
|---|---|
| 넘겨줄 자료 | 데이터 출처·버전, 코드 버전, 모델 또는 계산 규칙, 실행 방법, 최소 입력, 예상 결과. |
| 확인할 점 | 내 컴퓨터에서만 있는 경로·패키지·파일을 필요로 하는가? 단위와 가정을 이해할 수 있는가? |
| 완료 조건 | 다른 팀원의 확인 결과, 차이가 있다면 오류와 다음 행동까지 기록. |

**학생 기록:** 확인한 팀원, 실행 결과, 남은 의존 파일 또는 오류

### 58. 배포 단계인 팀은 운영 버전까지 대조한다

로컬에서 수정한 코드와 사용자가 접속한 서비스는 다를 수 있습니다. 배포 단계에 있는 팀은 저장소 변경, 자동 작업 결과, 실제 서비스 버전을 연결해 확인합니다.

| 확인할 내용 | 실제 자료와 해석 |
|---|---|
| 코드 기록 | 커밋 번호와 변경 목적. 비밀키·개인정보·대용량 원본은 저장소에 넣지 않음. |
| 운영 확인 | 검사·배포 작업 성공 여부, 실행 중 버전, 같은 입력의 실제 응답. |

**학생 기록:** 현재 완료 상태: 로컬 확인 / 커밋 / 배포 / 운영 확인 중 어디까지인가?

### 59. 제출: 대화보다 실행 근거가 중심이다
