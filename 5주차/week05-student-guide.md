이론·영상 관찰은 설치·코딩 없이 참여합니다. 최종 제출에는 GitHub 계정과 교수자가 지정한 제출 저장소 접근이 필요합니다. 4주차의 중고차·지하철 사례는 다시 강의하지 않습니다. 계산을 함께 풀고, 기존 시연에서 입력·결과·오류를 관찰한 뒤 팀의 설계를 종이나 문서에 적습니다. 아래 실행 명령은 선택 자료입니다.

필수 설명·계산 과정·퀴즈 해설·팀 작성 예시는 장표 본문에 모두 들어 있습니다. 발표자 노트나 첨부를 열어야만 개념을 이해하도록 구성하지 않습니다.

## 어떤 앱을 만드는 이야기인가요?

학생이 학습 앱의 연습문제 목록에서 풀 문제를 고릅니다. 문항은 문제 하나, 선택지는 고를 수 있는 답 후보입니다. 앱에서 문제를 연 순간부터 답을 제출할 때까지 흐른 시간을 여기서는 풀이시간이라고 부릅니다. 그 실제 시간은 제출 뒤에야 알 수 있습니다.

우리가 만들 기능은 **문제를 고를 때 예상 시간을 보여 주는 것**입니다. 과거의 문제 정보와 실제 시간을 함께 보고 계산 방법을 정한 다음, 새 문제의 정보만 넣어 예상합니다. 예상은 실제와 다를 수 있으므로 차이도 확인합니다.

장표 3번은 한 번의 풀이가 기록되는 과정, 5번은 과거 기록으로 방법을 만드는 과정, 21번은 자료를 나누는 이유, 34번은 앱과 서버가 주고받는 과정을 그림으로 설명합니다. 그림 확대 버튼으로 크게 볼 수 있습니다.

## LiveClass에서 질문 풀기

질문 장표의 입력 칸에 숫자·선택·자기 생각을 남깁니다. **내 답과 해설 비교**를 누르면 연결된 해설에서 내 답과 정답 또는 예시를 나란히 볼 수 있습니다. **질문으로 돌아가 수정**으로 다시 풀 수 있으며, 같은 브라우저·학생 계정에서는 새로고침해도 답을 유지합니다.

숫자·선택형은 정오를 확인하고 서술형은 예시와 직접 비교합니다. 강사가 진행 중인 질문의 **강사에게 답안 전송**을 눌러 제출하고 전송 완료 표시를 확인합니다. 개별 열람 중 작성한 답도 내 브라우저에 보관됩니다.

## 필수 제출

모든 최종 산출물은 **PR(변경 사항 반영 요청)**로 제출합니다. [학습지](week05-workbook.md)의 계산·해석 답, 팀 설계, 정상·실패 상황표, 동료 의견의 반영 여부, 팀원별 기여와 미완료 사항을 저장소 문서에 담습니다. 종이는 초안에 사용할 수 있지만 최종 내용은 파일로 정리해 PR에 포함합니다.

교수자가 지정한 제출 저장소·대상 브랜치로 PR(변경 사항 반영 요청)을 만들고, PR 주소에서 제출 파일과 변경 내용을 확인합니다. Push만으로는 최종 제출이 끝나지 않습니다. 예시 파일명은 week05-submission.md이며 저장소의 안내가 있으면 그 규칙을 따릅니다. PR 생성은 제출이고, Merge 여부는 검토 후 결정됩니다.

모델 실행을 못했더라도 관찰 결과·설계·미완료 이유를 PR(변경 사항 반영 요청)로 제출합니다. 터미널 사용이 어려우면 GitHub 웹 편집기를 사용합니다. 계정이나 권한 문제가 있으면 교수자에게 지원을 요청하고 PR 제출까지 마칩니다.

## GitHub PR(변경 사항 반영 요청) 설명

61–72장의 교육용 재구성 화면에서 원본→Fork→작업 브랜치→Commit·Push→PR(변경 사항 반영 요청)→검토의 흐름을 봅니다. 학생은 원문·수정안·이유·확인 방법을 적어 같은 검토 과정을 연습합니다. 최종 PR을 만들 때 [GitHub 공식 문서 기반 안내](git-pr-guide.md)를 따릅니다. 터미널을 사용하지 않는 웹 편집 경로도 안내합니다. 수정 제안을 받기로 합의한 저장소를 사용하며 임의 외부 저장소에 제출하지 않습니다.

장표의 선택 실행은 강사 제공 모델 `inference/model/model.json`부터 사용합니다. 아래 안내는 직접 학습한 모델까지 이어 보는 추가 경로입니다. 두 모델의 출처를 구별합니다.

## 선택 실행: 환경 준비

통합 ZIP(압축 파일)을 새 폴더에 모두 풉니다. 최상위에서 README.md, training/, inference/가 보여야 합니다. Python 3.11과 초기 패키지 설치용 인터넷을 준비하고 공통 수업에서는 설치하지 않습니다. 직접 실행을 선택할 때만 준비합니다. 학생 AWS(아마존 클라우드 서비스) 계정·IAM(신원·접근 권한 관리) 설정 권한은 필수 조건이 아닙니다.

macOS/Linux, ZIP(압축 파일)을 푼 최상위 폴더:

```sh
python3.11 -m venv .venv # 이번 묶음 전용 환경
.venv/bin/python -m pip install -r training/requirements.txt -r inference/requirements.txt # 학습과 호출 패키지
```

Windows PowerShell:

```powershell
py -3.11 -m venv .venv # 이번 묶음 전용 환경
.\.venv\Scripts\python.exe -m pip install -r training/requirements.txt -r inference/requirements.txt # 패키지 설치
```

아래 `../.venv/bin/python`은 Windows에서는 `..\.venv\Scripts\python.exe`로 바꿉니다. Windows 명령은 안내이며 이번 검증은 macOS에서 수행했습니다. 경로에 한글·공백이 있으면 `cd "실제 폴더 경로"`로 이동합니다.

## 선택 실행: 학습·평가·저장

```sh
cd training # 학습 코드 위치
../.venv/bin/python train.py --out out-01 # 품질·분할·학습·검증 선택·평가·저장
../.venv/bin/python reload.py --model out-01/model.json --input input/minimal-input.json --expected out-01/reload-expected.json --out out-01/my-reload.json # 새 프로세스에서 재로딩
```

원본 36행 중 기본 품질 검사 통과 33행을 학습 19행·검증 6행·재사용 평가 8행으로 나눕니다. 한 행은 교육용 풀이시간 예시이며 실제 학생 자료가 아닙니다. `split-manifest.csv`의 역할, `selection-before-test.json`의 선택 근거, `evaluation.json`의 오차, `reused_test-predictions.csv`의 각 입력·정답·예측을 읽습니다. 결과 파일은 모두 out-01 아래에 있습니다.

정답과 예측의 차이에서 부호를 없애 평균 낸 값이 MAE(평균절대오차)입니다. 강사 참고 실행은 재사용 평가 8행에서 기준선 7.75초, 모델 약 1.062초였습니다. 자기 결과를 먼저 읽고 비교하세요. 평가를 이미 본 작은 교육용 자료이므로 새로운 학생·문항에 대한 성능으로 주장하지 않습니다.

이미 out-01이 있으면 out-02 등 새 이름으로 실행하고 아래 명령도 같은 이름으로 바꿉니다. 실행하지 못하면 미완료 이유를 남깁니다. `inference/model/model.json`은 강사 제공 모델이므로 이것으로 연습할 때 자기 학습 완료로 제출하지 않습니다.

## 선택 실행: 함수·HTTP(웹 요청·응답 통신 규약)·배치 사용

```sh
cd ../inference # 학습 폴더에서 추론 폴더로 이동
../.venv/bin/python core.py --model ../training/out-01/model.json --input inputs/normal.json --out function-01.json # 같은 입력 한 건
../.venv/bin/python serve.py --model ../training/out-01/model.json --port 8055 # 터미널 A: 서버 유지
```

터미널 B도 inference 폴더에서 실행합니다.

```sh
../.venv/bin/python client.py --url http://127.0.0.1:8055/predict --input inputs/normal.json --out http-valid.json # 정상 요청
../.venv/bin/python client.py --url http://127.0.0.1:8055/predict --input inputs/missing.json --out http-missing.json # 필수 값 누락
../.venv/bin/python batch.py --model ../training/out-01/model.json --input inputs/batch.jsonl --out out-batch-01 # 여러 요청
```

`normal.json`은 글자 205개·선택지 2개입니다. 결과 단위는 초이고 강사 예제는 약 31.245초입니다. `function-01.json`, HTTP(웹 요청·응답 통신 규약) 응답, 배치의 같은 입력에서 예측값·모델 해시를 비교합니다. `out-batch-01/meta.json`과 `results.jsonl`은 입력 5건·정상 4건·실패 1건과 행별 이유를 담습니다. 오류 요청은 422 응답을 확인합니다. 200 응답은 처리 성공이며 정확도 증거가 아닙니다.

터미널 A에서 Ctrl+C로 서버를 끝냈다가 같은 명령으로 다시 시작합니다. 터미널 B의 정상 요청 명령에서 출력만 `http-restart.json`으로 바꿔 재실행합니다. 같은 입력의 예측은 절대 차이 0.000000001초 이내인지 확인합니다. 요청 ID·측정시간은 달라도 됩니다. 마지막에 A에서 Ctrl+C로 서버를 종료하고 모델·결과는 보존합니다.

모델 출처 오류가 나면 버전과 학습 조건을 확인합니다. 자기 학습 모델은 옆의 evaluation.json에 기록된 모델 해시를 대조합니다. 이 기록은 파일 혼동을 찾기 위한 것으로 외부 파일의 신뢰성을 보증하지 않습니다. 학습 환경에 따라 마지막 소수 자리가 달라질 수 있으므로 강사 모델과의 바이트 동일성을 요구하지 않습니다. 이 교육용 호출 코드는 정해진 샘플의 출처·모델 형식·같은 실행의 해시를 확인하므로 임의 팀 모델의 범용 서버가 아닙니다. 해시 검사를 지워 억지로 통과시키지 않습니다. 팀은 자신의 형식·입력 계약에 맞는 로더를 사용합니다.

- 학습 오차가 0초인 방법이 새 문항에서도 좋은지, 어떤 자료로 확인해야 하는지 설명합니다.
- 항목 누락, null, 숫자처럼 생긴 문자열을 서버의 입력 규칙에 따라 구별합니다.
- 처리 상태 200, 예상 31.2초, 응답 대기 0.1초, 실제 50초가 각각 무엇을 뜻하는지 설명합니다.
- 배치 실패 행을 지우면 원래 다섯 요청 중 몇 건을 처리했는지 설명합니다.

각 질문의 계산 과정과 오답 해설은 바로 뒤의 장표 본문에서 확인할 수 있습니다.
