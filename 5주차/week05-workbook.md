## 0. 먼저 앱의 사용 장면을 이해하기

학생은 학습 앱의 문제 목록에서 풀 문제를 고릅니다. 문항은 문제 하나이고, 풀이시간은 문제를 연 순간부터 답을 제출할 때까지 흐른 시간입니다. 앱에는 문제를 고르는 순간 예상 시간을 표시하려 합니다.

![한 번의 풀이가 기록되는 과정](concept-images/attempt-timeline.webp)

- 문제를 고를 때 이번에 실제로 걸릴 시간을 알 수 있나요? **아직 알 수 없습니다. 풀이가 끝나야 나오는 값이기 때문입니다.**
- 실제 시간은 언제 기록할 수 있나요? **답을 제출한 뒤, 시작 시각과 종료(제출) 시각의 차이로 기록할 수 있습니다.**
- 아직 풀지 않은 문제의 시간을 예상하려면 어떤 과거 기록을 이용할 수 있나요? **이미 끝난 다른 풀이들의 문제 정보와 그때 실제로 걸린 시간 기록입니다.**

비교할 설명: 고를 때는 아직 모릅니다. 제출한 뒤 시작·종료 시각의 차이를 기록합니다. 이미 끝난 풀이의 문제 정보와 실제 시간을 이용해 계산 방법을 정할 수 있습니다.

## 1. 같은 문항에서 오차 비교

실제 시간은 가12초·나18초·다35초입니다. 모든 문항에18초를 답하는 기준선의 각 오차와 MAE(평균절대오차)를 계산하세요.

- 각 오차: 가**6**초 / 나**0**초 / 다**17**초. 합계**23**초 ÷ **3**건 = 평균**7.67**초.
- 설명용 식이12·22·32초를 답했다면 각 오차**0** / **4** / **3**초, MAE**2.33**초.
- 이 세 문항에서 더 작은 오차인 방법은**설명용 식(2.33초 < 7.67초)**입니다. 새 문항에서도 더 좋다고 단정할 수 없는 이유는**이 세 문항의 정답에만 맞춰 계산한 값이라, 다른 문항에서도 잘 맞는다는 보장(일반화 성능)이 없기 때문**입니다.
- +10초와−10초의 오차가 서로 취소되면 안 되는 이유는**부호를 남긴 채 평균을 내면 큰 오차들이 서로 상쇄되어 평균이 0에 가까워지고, 실제로는 예측이 많이 틀렸는데도 성능이 좋아 보이게 되기 때문**입니다.

## 2. 학습·평가 원리

- 학습 / 검증 / 평가 자료가 각각 맡는 역할: **모델의 계수·파라미터를 데이터에 맞춰 정하는 데 사용** / **학습 중 방법이나 설정(하이퍼파라미터)을 비교·선택하는 데 사용** / **최종 확정된 모델의 성능을 마지막에 한 번만 확인하는 데 사용**.
- 평가 정답을 보고 계속 방법을 바꾸면 생기는 문제: **평가 자료에 맞춰 모델을 반복 조정하게 되어 평가 자료가 사실상 학습 자료처럼 되고(정보 누수), 실제로 새로운 자료를 만났을 때는 성능이 떨어집니다.**
- 예측할 순간에는 알 수 없는 정보를 입력에 넣은 사례를 하나 쓰세요: **`train_vote_average.py`의 `popularity`·`vote_count`가 그 예입니다. 코드 주석에도 "평점과 같은 시점에 쌓이는 값이라 입력으로 쓸지 팀이 정해야 함"이라고 되어 있습니다. 개봉 직후(투표가 쌓이기 전) 평점을 예측하려는 상황이라면 이 두 값은 예측 시점에 아직 존재하지 않는 정보입니다.**
- (200−150)÷50=**1**입니다. 변환 기준까지 모델과 함께 저장해야 하는 이유: **예측할 때도 학습 때와 똑같은 척도(최소·최대, 평균·표준편차 등)로 변환해야 같은 입력이 같은 값으로 해석됩니다. 기준이 달라지면 같은 입력도 다른 값으로 변환되어 예측이 틀어집니다.**
- 같은 입력의 예측이 재시작 전후 같다는 것과 정확하다는 것의 차이: **재시작 전후 같다는 것(재현성)은 모델이 같은 입력에 항상 같은 출력을 낸다는 뜻일 뿐이고, 정확하다는 것(정확성)은 그 출력이 실제 정답에 가깝다는 뜻으로 서로 다른 성질입니다.**

## 6. 동료 문서 수정 제안

원래 문장**`dataset.md`: "최고 평점 영화 데이터셋은 각 영화에 대한 필수 메타데이터를 포함하는 10,000편의 영화로 구성된 종합적인 컬렉션"이며, 열 설명에 `original_title`·`original_language`가 포함되어 있음** / 수정 문장**"실제 `top_rated_movies.csv`는 헤더를 제외하고 18,520행이며, id 중복을 제거하면 9,959행이 남습니다. 또한 이 CSV에는 `original_title`·`original_language` 열이 없고, 실제 열은 `id, title, overview, release_date, popularity, vote_average, vote_count` 7개입니다."** / 수정 이유**`dataset.md`가 설명하는 행 수·열 구성과 실제 파일이 달라, 이 문서만 보고 전처리 코드를 짜면 존재하지 않는 열(`original_language`)을 참조하는 실수가 생길 수 있음. `train_vote_average.py`의 코드 주석에서도 "top_rated_movies.csv에는 original_language 열이 없음"이라고 이미 확인됨** / 확인 방법**`pandas.read_csv`로 `df.shape`와 `df.columns`를 출력해 대조. 실제 실행 결과: 18,520행 × 7열, id 중복 8,561행**.

이 제안서를 포함한 모든 최종 결과는 저장소 문서로 정리해 PR(변경 사항 반영 요청)로 제출합니다. PR 본문에 팀원별 기여·확인한 범위·미완료 사항을 적고, 제출처와 변경 파일을 확인한 뒤 PR 주소를 남깁니다. 직접 실행한 경우에만 별도로 명령·환경·실제 결과를 첨부합니다.

## 수업 중 추가 계산·판단

- 실제 10·20·30초, 예상 14·18·36초: 차이 크기**4**·**2**·**6**초, MAE(평균절대오차)**4**초. 12초는 세 문항의 오차를 그대로 더한 총 절대오차 합(4+2+6)이고, 4초는 그것을 문항 수(3건)로 나눈 평균(MAE)입니다.
- 학습 자료의 오차가 0초인 모델이 새 문항에서 7초, 다른 모델이 2초 틀렸다면 어떤 결과를 기준으로 판단할까요? **새 문항(학습에 쓰이지 않은 자료)의 결과인 7초 대 2초로 판단해야 하며, 2초 틀린 모델을 선택합니다. 학습 자료 오차가 0초라는 것은 오히려 그 자료에 과적합되었다는 신호일 수 있습니다.**
- 상태 200, 예상 31.2초, 응답 대기 0.1초, 실제 50초: 예측 오차**18.8**초. 빠른 응답과 정확한 예측은 같은 뜻인가요? **아닙니다. 응답 대기 0.1초는 서버가 빠르게 답했다는 뜻일 뿐이고, 예측값이 실제와 18.8초나 차이 나는 것은 별개의 문제(정확도)입니다.**
- 입력 5건 중 실패 1건을 지우면 처리 대상은**4**건입니다. 실패 입력을 수정하는 것과 어떤 차이가 있나요? **수정하면 5건 모두를 처리해 온전한 결과를 얻을 수 있지만, 지우면 처리 대상 자체가 줄어들고 실패 원인도 기록에 남지 않아 문제를 숨기는 셈이 됩니다.**
